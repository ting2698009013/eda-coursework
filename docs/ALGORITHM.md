# 算法与实现说明

## 研究问题

同一个布尔函数可以有多种逻辑结构。ABC 提供一组保持功能不变的优化操作，但不同操作顺序可能得到不同的映射结果。本项目研究在预算有限时，怎样选择顺序，以及直接观察 LUT 结果是否值得额外的计算开销。

## 几个必要概念

- **AIG**：由二输入与门和反相连接组成的逻辑图，用作综合过程中的统一表示。
- **LUT**：查找表。K 输入 LUT 能实现任意 K 输入布尔函数。本项目统一使用 K=6 的映射模型。
- **层数**：输入到输出的最长逻辑级数。AIG 层数和 LUT 层数是两个不同阶段的指标。
- **等价验证**：检查两个电路对所有输入是否给出相同输出。这里调用 ABC 的组合等价检查器。

## 优化操作

| ABC 命令 | 通俗解释 |
| --- | --- |
| `balance` | 利用逻辑结合律调整结构，尽量减少逻辑深度 |
| `rewrite` | 用更合适的小结构替换局部逻辑图 |
| `rewrite -z` | 也允许当下节点数不减少的替换，为后续优化留下机会 |
| `refactor` | 对局部逻辑重新分解和组织 |
| `refactor -z` | 允许节点数暂时持平的重新分解 |

这些操作由 ABC 实现，本项目不声称重新实现了它们。自主实现部分是搜索、选择、预算控制、实验与分析。

## 固定基准

`resyn2` 展开为：

```text
balance
rewrite
refactor
balance
rewrite
rewrite -z
balance
refactor -z
rewrite -z
balance
```

所有最终映射都执行 `if -K 6`。程序使用 `-s` 启动 ABC，忽略用户的 `abc.rc`，并直接展开以上命令，避免别名和用户环境影响实验。

主目标可以写为：在功能等价、LUT 层数不超过 resyn2 的条件下，最小化 LUT 数量。对于满足约束的候选，先比较 LUT 数，再比较层数。中间候选若暂时违反深度约束，仍可能占用探索位置，但不能直接作为最终可行解。

## 束搜索

1. 从原始电路开始。
2. 给当前保留的每条序列各追加一种操作。
3. 用 ABC 执行候选序列，获得指标。
4. 保留最多 4 个候选，继续下一轮。
5. 达到最大长度、调用次数或时间预算后停止。

贪心方法相当于每轮只保留一个候选。探索分支版本保留 3 个排名靠前的结构，再从剩余结构随机保留一个，试图降低过早剪枝的风险。它是否有效由消融实验判断，不能由设计直觉保证。

## AIG 指标与 LUT 反馈怎样公平对比

`aig_beam` 先只运行逻辑优化并读取 AIG 节点数、AIG 层数。每轮筛选后，仅将保留的候选送去映射。

`lut_beam` 则映射每一个候选，再根据 LUT 数和 LUT 层数决定保留谁。

这两种方法的映射开销不同，所以实验既记录 ABC 调用次数，也限制实际运行时间。映射保留候选的额外调用会计入同一预算。调用次数相等并不意味着 CPU 工作量相等，报告必须同时看时间协议。

## 防止实现错误的关键约束

**保留 AIG 后再映射。** `write_aiger -s candidate.aig` 位于 `if -K 6` 之前。后续搜索继续处理原 AIG，不把已映射网表重新转回去，避免改变研究问题。

**保留端口名称。** `write_aiger -s` 中的 `-s` 保存输入输出名称。否则 CEC 可能无法匹配两个网络的端口。早期开发实验发现并修复了这个问题。

**结构去重不等于功能去重。** 所有正确候选本来就应该功能相同。不能把它们都合并，也不能因为节点数相同就判定结构相同。程序解析 AIGER 的输出与门编码，对电路数据部分计算 SHA-256，排除端口名称和含有写入时间的注释。这是保守的结构去重，不做图同构判断。另存完整文件的 SHA-256，用于检查结果文件是否被改动。

**真实时间包含实际开销。** 搜索计时包含 ABC 启动、执行、临时文件和候选选择。基准准备、最终导出和等价检查单独记录。WSL 环境先把校验过的同一个 ABC 二进制复制到 Linux 临时目录，避免 Windows 挂载盘的额外分页开销影响大量短进程。

**失败不当作通过。** CEC 返回值细分为 equivalent、not_equivalent、timeout、unknown 和 error。只有明确通过才纳入有效结果。

## 扩展方法与实现边界

### 整序列局部搜索

扩展实验增加了 `sequence_local`。它直接处理长度为 10 的完整序列：先在预算内重新评估 resyn2，然后随机替换一个位置的操作。若可行性、LUT 数和层数组成的目标不差于当前状态，就接受修改；目标相同时也允许移动。连续若干次试探没有严格改善后，随机生成一条完整序列重启。重启可以暂时进入较差状态，但单独保存的全局冠军始终满足深度约束。

初始化、变异和重启的 ABC 调用都计入预算。重复序列不重新评估，算作未改善试探。每一步的候选、接受决定、停滞计数与父候选保存在 `local_steps.jsonl`；随机性由种子控制。开发实验只比较停滞阈值 5、10、20，具体选择与新电路结果分开记录。

### 评分机制对照

`aig_beam_mapped` 只用于诊断：每个候选都做 LUT 映射，但保留路径仍按 AIG 节点数、AIG 层数排序。它与 LUT 束搜索映射同样类型的候选，便于观察评分变化。它不代表原版 `aig_beam` 的真实效率，因为原版只映射筛选后保留的候选。

两个诊断版本都将已评估的可行最优候选保存为全局冠军。淘汰某候选仅阻止继续扩展它的后继，并不会删除已经找到的最优输出。因此“层内最佳候选被剪掉”不等于“最终结果一定变差”。

### 预算解释

当前原型为每个候选从原始输入重放完整操作序列，没有实现增量执行前缀。这便于重现，但会重复计算共同前缀；计时结论限于这一实现。`completed_tree` 表示完成固定束宽和十层流程，不代表遍历所有序列。随机搜索的 `completed_space` 则表示指定长度的全部不同序列都已经尝试，成功与失败调用数另行记录。

## 已知范围

当前只支持组合电路。没有进行重定时、寄存器优化、真实 FPGA 打包与布线，也没有测量功耗。最大序列长度为 10、束宽为 4 是本次固定实验配置，不能当作普适最佳参数。
